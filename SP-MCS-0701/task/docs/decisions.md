# 决策记录

按日期追踪决策。资源管理导航以 2026-10-29 决策为准；下方阶段 1 的顶部一级入口方案仅保留为历史记录，不作为现行实现依据。

## 2026-10-29：资源管理改为侧栏入口

用户决定将资源管理从头部移至任务规划系统左侧，作为与系统管理平级的可展开菜单，包含卫星管理、光学载荷管理、天线管理。子页在任务规划系统内容区显示，不跳转至独立站点；资源管理仍由独立仓库维护，也可单独运行。头部原位置作为“接入与权限系统”占位。本条修正此前单项外链方案。

## 2026-10-29：预览启动频率更正

当前 `scripts/Register-PrototypePreviewWatchdog.ps1` 使用 `ONLOGON`，当前用户登录时检查一次任务规划预览服务；早期每 5 分钟检查方案已取消。资源管理 5176 服务由其独立仓库启动。

## 2026-09-17 本机预览服务守护（执行频率已被 2026-10-29 决策取代）

- 预览服务由独立隐藏 Vite 进程运行，并以 HTTP 健康检查判断可用性，不依赖遗留 PID 文件。
- 注册当前用户的每 5 分钟计划任务，服务不可用时自动调用启动脚本恢复；任务支持电池模式，端口已被未知进程占用时不强制结束该进程，避免影响其他本机服务。

## 2026-09-16 复用既有业务弹窗与页面

- 计划详情、手动创建计划和手动测控时段表单均作为共享组件复用，不为关联入口创建平行版本。
- 批量规划计算允许多选并要求确认；区域筹划仅允许单选，以避免将多个任务内容混入同一筹划上下文。
- 跨页面跳转只携带已知任务字段；缺少的区域计算专有字段保持待确认，不用其他任务的数据补全。
- 手动测控时段列表不显示针对某条历史记录的全页提示；异常时间保留在记录中，新增和编辑仅通过表单校验阻止无效保存。

## 2026-09-16：参数管理采用配置集内分组表

- 背景：真实参数管理样例将基础、卫星型号和任务模板参数按业务类别拆分为多个相邻表，而不是使用一张无边界的平铺长表。
- 决定：页面保留“配置分类 → 配置集”的导航层级；编辑区按原始组序渲染分组标题与独立表格，值列保持可编辑，选中行在右侧显示参数说明。
- 原因：分组能够让平台约束、载荷约束、任务模板和 IPU 类参数保持业务语义边界，同时不丢失真实样例的完整行清单。
- 影响：保存仍仅产生本地原型反馈；没有在样例中显示的值不补造，以“—”保留。

## 2026-09-16：字典编辑补充备注与生效开关

- 背景：补充的字典编辑截图明确展示了名称、字典值、备注多行输入和“是/否”生效状态开关。
- 决定：在现有所属分类、名称和字典值基础上新增备注字段，并以生效状态开关替代下拉选择；列表状态列仍保持“生效/停用”文字标签。
- 影响：备注随新增和编辑一并写入本地 Mock；删除确认、分类绑定和真实后端边界不变。

## 2026-09-16：上注文件登记采用三分区新增/编辑弹层

- 背景：补充截图明确了上注文件登记的新增与编辑均由原文件基本信息、分卷文件管理和执行结果记录三块组成，且每块有独立保存入口。
- 决定：两类入口复用同一全宽 Dialog；原文件区保留软件、版本、卫星、路径、MD5、分卷路径和备注，分卷区支持识别和保存清单，结果区记录最终结果与备注。
- 影响：路径选择器和真实分卷识别仍只提供本地模拟反馈；保存执行结果后才将新增或编辑后的记录回写到本地列表，真实文件系统与后端处理规则不作假设。

## 2026-09-16：规划计算管理遗漏功能补齐

- 决定：在既有“规划计算、规划配置、算法管理”后补入“紧急任务处理”和“参数管理”，两页沿用白色画布与全宽工作台规格。
- 依据：真实系统 HTML 菜单明确列出两个入口；应急页面确认了筛选、处理记录与处理配置，参数管理 3 个页面确认了三类配置、版本集合和参数表。
- 边界：应急处理不提供未经证实的重新处理命令；参数具体值没有证据时保持“—”。涉及规划选择的算法启停必须确认，所有保存均为本地原型交互。

## 2026-09-09：阶段 1 采用独立 Vue 产品仓库

- 背景：工作台已有同名 React 产品，但用户要求新建产品并采用默认 Vue Element Plus 技术栈。
- 决定：新建 `task-planning-prototype`，配置栈固定为 `vue-element-plus`，不迁移或修改既有 React 仓库。
- 原因：遵守产品边界和双栈隔离门禁。
- 影响：仅使用 Vue 3、TypeScript、Vite、Element Plus、Vue Router、Pinia。

## 2026-09-09：线上页面是唯一业务证据

- 背景：阶段 1 要求不得臆造字段、入口和业务流程。
- 决定：已观察内容直接映射；未安全触发的高风险弹层、完整枚举和跳转目标统一标为「待确认」。
- 原因：避免把合理猜测误写成已验证行为。
- 影响：地图使用无交互证据示意；批量入口不连接真实业务。

## 2026-09-10：HTML 仅作结构证据，不作代码来源

- 背景：新增任务列表和详情页保存 HTML，用于纠正表格与日志细节。
- 决定：提取可见结构和样式事实后重新实现；不复制打包脚本、内联样式、冗余资源或旧实现习惯。
- 原因：原型需要比旧系统更规范、精致且可维护。
- 影响：采用无竖线弹性表格和独立日志侧栏；Element Plus 按实际组件注册。

## 2026-09-10：采用通用产品品牌 SP-MCS

- 背景：原系统品牌仅作为页面结构证据，不能成为通用产品原型的产品名称。
- 决定：产品统一命名为“星枢任务控制系统（SP-MCS，Stellar Pivot Mission Control System）”，工程标识使用 `SP_MCS`。
- 原因：兼顾独立品牌辨识度与航天任务控制系统的行业命名惯例。
- 影响：头部改为 SP-MCS 品牌标识和中文系统名；完整名称、简短介绍与术语释义收纳在低干扰的“系统说明”入口中。

## 2026-09-10：顶层导航按独立产品边界重构

- 背景：参考页面属于更大的“地面系统”，原型只抽取其中一个系统的任务规划能力作为独立产品。
- 决定：顶部不再复刻地面系统一级菜单，改为产品内部的五系统导航；阶段 1 只开放任务规划系统，左侧只承载该系统的功能菜单。
- 原因：避免把上级平台的信息架构错误带入独立产品，同时保留未来产品模块的明确位置。
- 影响：轨道计算、可视化仿真、遥控管理和遥测监视仅呈现禁用入口，不出现对应左侧菜单。

## 2026-09-10：顶部采用品牌区与分段导航双区布局

- 背景：品牌名称与说明入口在原 210px 区域中过于拥挤，平铺式系统入口的选中层级也不够清晰。
- 决定：品牌区和左侧导航统一扩展，并使用响应式宽度；五个系统入口收纳进深色分段导航轨道，当前系统使用实体蓝色选中态。
- 原因：增强品牌完整性、模块切换辨识度与桌面端视觉秩序，同时保持既有交互范围不变。
- 影响：桌面宽度为 250px，1280px 以下为 240px，1100px 以下为 230px；筛选区同步压缩标签间距，避免工作区缩小导致控件文字截断。

## 2026-09-10：系统选中态采用“星轨锚点”方案

- 背景：分段容器和蓝色填充仍然形成明显按钮感，与一级系统导航的层级不符。
- 决定：采用评审方案 A，取消导航容器、选中背景、边框与阴影；仅使用高明度文字和 20px 渐隐短线表示当前系统。
- 原因：选中状态清晰但不争夺业务操作按钮的视觉注意力，且短线保留轻量的星轨品牌隐喻。
- 影响：悬停时短线扩展到 28px；键盘聚焦保留低对比度轮廓，未开放系统交互范围不变。

## 2026-09-10：资源管理提升为跨系统一级入口（已被 2026-10-29 决策取代）

- 背景：资源管理后续会同时影响任务规划、轨道计算、可视化仿真、遥控管理和遥测监视，不属于任务规划系统的内部功能。
- 决定：从左侧任务规划菜单移除资源管理，在顶部作为第六个独立一级入口，并使用轻微分隔表达公共能力边界。
- 原因：导航层级与功能影响范围保持一致，避免把跨系统能力误解为任务规划的子模块。
- 影响：阶段 1 尚无资源管理页面证据，因此入口保留为“页面待建设”的禁用状态。

## 2026-09-10：筹划配置作为筹划计算弹层证据

- 背景：用户提供了“筹划计算”“筹划配置”“大区域筹划”三个 HTML，并要求以两个业务页面结束阶段 1。
- 决定：将“筹划计算”和“大区域筹划”实现为独立路由；将“筹划配置”识别为筹划计算的设置与日志弹层证据，不额外制造第三个页面。
- 原因：保存页面中的可见结构显示筹划配置与日志均叠加在筹划计算页面上，符合原系统实际交互边界。
- 影响：左侧筹划计算与大区域筹划入口可导航；设置、日志、开始筹划与开始计算均在对应页面内闭环。

## 2026-09-10：大区域地图采用明确标注的脱机示意

- 背景：证据能确认坐标、比例尺、目标区域入口与地图控件，但无法确认真实边界和地图服务。
- 决定：保留地图骨架和全部已知单位数据，使用不代表真实地理边界的示意区域，并直接标注“范围形状待确认”。
- 原因：既验证页面布局与操作层级，又避免把视觉占位误解为业务数据。
- 影响：后续接入地图服务时可替换地图内部实现，不改变任务信息、业务内容和计算操作结构。

## 2026-09-10：补充完成态按任务证据隔离

- 背景：后续补充设计提供了 RW202608260121005 的完整计算结果，但此前页面示例为 RW202609090121001。
- 决定：两个任务都保留为可载入证据；只有 RW202608260121005 可展示补充页面给出的 4 条条带结果，其他任务不复用该结果。
- 原因：避免把一个任务的面积、覆盖率、时间和条带数据错误套用给另一个任务。
- 影响：默认示例改为具备端到端证据的 RW202608260121005；`?result=success` 提供完成态评审入口。

## 2026-09-10：大区域筹划限制内容宽度并精简结果操作

- 决定：大区域筹划主体最大宽度设为 1360px，在更宽工作区内居中；移除计算完成态的计算日志入口和日志区域。
- 原因：无限拉伸会削弱地图、任务卡与统计卡之间的视觉比例；本轮评审确认结果页不需要计划日志功能。
- 影响：1024px、1280px 下仍使用全部可用宽度，超宽屏显示稳定留白；筹划结果分析止于条带明细。

## 2026-09-10：任务地图随信息列等高

- 决定：任务加载区左侧改为纵向弹性布局，地图吸收右侧任务卡形成的剩余行高，侧摆控制保持固定高度。
- 原因：固定地图高度在右侧信息较多时会在左列底部形成无意义空白，破坏双列对齐关系。
- 影响：地图与右侧“任务信息 + 业务内容”整体底部对齐；不同桌面宽度下仍保留地图最低可用高度。

## 2026-09-10：阶段 2 优先修复原型可信度

- 背景：两位独立 UI 专家评审均指出，三个页面的主要风险来自假交互、页面标题不一致和模拟数据性质不清，而不是视觉装饰不足。
- 决定：统一页面标题；补齐查询、刷新、地图缩放/复位、条带选择与确认取消分支；就近标识模拟、历史和计划数据；不改变字段、入口、任务数据或后端业务规则。
- 原因：可操作入口必须可演示，无法确认的能力应明确限制，才能满足阶段 2 的评审可信度。
- 影响：三个页面的标题层级和反馈模型统一；列表、筹划记录和地图的本地交互可以闭环。

## 2026-09-10：阶段 2 争议项维持既定业务边界

- 决定：保留顶部“资源管理”、单页签骨架、左侧待建设分组、已确认的木铎卫星样例名和证据总数；不自行打通列表批量入口到子页面。
- 原因：“资源管理”是用户明确要求的跨系统一级入口；其余事项涉及信息架构、字段命名、分页数据真实性或批量参数规则，当前证据不足。
- 影响：相关视觉或交互问题记录到阶段 2 闭环文档并给出备选方案，待业务确认后再处理。

## 2026-09-10：移除未使用的全局状态初始化

- 决定：移除未创建任何 Store 的 Pinia 初始化与直接依赖，并将重复的 `PrototypeState` 合并到公共类型文件。
- 原因：当前三页均使用页面本地状态；保留未使用的全局状态容器只增加包体和认知成本。
- 影响：不改变页面行为；后续确有跨页共享状态时可按实际需求重新引入 Pinia。

## 2026-09-10：阶段 3 建立单一语义主题来源

- 背景：三个试点页面已经定稿，需要把可复用视觉规则沉淀为后续全量还原的共同基线。
- 决定：新增 `src/styles/theme.css` 作为 `--sp-*` 语义令牌唯一来源，并将 Element Plus 主题变量映射到同一组令牌；`docs/ui-spec.md` 使用完全一致的名称和值。
- 原因：避免文档与实现漂移，也避免页面各自复制主色、字体、间距和边框定义。
- 影响：页面标题、应用壳、卡片、表格及响应式布局引用全局令牌；地图几何、轨道/条带配色、时间卡比例和证据优先级颜色仍保留为领域例外，不上升为全局规则。

## 2026-09-10：阶段 4 按业务分组分批交付

- 背景：全量输入包含 34 个顶层 HTML 页面，用户要求先完成几页验收，避免一次性还原造成方向性返工。
- 决定：第一批选择同属“规划计算管理”的规划计算、规划配置、算法管理；手动触发、配置编辑、新增算法作为页面状态而不是额外菜单页。
- 原因：三页导航连续、数据和操作互相关联，能够同时验证列表、配置、日志、弹层和高风险确认模式。
- 影响：后续页面暂不实现；第一批验收通过后再进入下一业务组。

## 2026-09-10：不从新增算法推导编辑算法

- 背景：证据确认了新增弹层和列表“编辑”入口，但没有确认编辑表单字段、不可编辑项及保存规则。
- 决定：新增算法按证据实现；编辑入口保留并明确提示“待确认”，不假定与新增表单完全相同。
- 原因：复用表单是代码层面的便利，不能替代业务证据。
- 影响：算法编辑将在取得真实页面证据后闭环；当前不影响列表、添加和删除确认演示。

## 2026-09-10：页面宽度分为全宽与限定宽度两种规格

- 背景：规划计算同时包含固定控制区与宽记录表，改成单列或统一限制最大宽度都会浪费横向空间；配置页在超宽屏铺满则会拉散字段阅读路径。
- 决定：全宽自适应页不设内容上限，使用全部工作区；限定宽度页统一使用 `--sp-content-contained-width: 1200px` 并居中。任务需求列表和规划计算归入全宽型，规划配置归入限定型。
- 原因：用页面信息密度和宽度收益选择布局，而不是让所有页面服从同一个容器宽度。
- 影响：规划计算恢复左侧弹性控制区、右侧记录区的横向骨架；表格不足时只在内部滚动。大区域的 `1360px` 上限继续作为已批准的地图领域例外。

## 2026-09-10：规划计算采用主面板标题并强化左侧控制区

- 背景：页面级“规划计算”与紧接其后的左侧面板同名，没有补充导航或业务信息，同时占用垂直空间；补充设计稿对左侧操作、动态和日志层级已有更完整方案。
- 决定：移除该页 `PageHeader`；以左侧面板标题承担页面内容标题。主操作使用高识别蓝色按钮，动态状态和进度使用成功语义，日志改为浅色卡片流。
- 原因：减少重复信息，并让执行入口、状态与日志形成连续的操作路径。
- 影响：右侧记录区与既有字段、筛选、分页不变。原“模拟数据”就近标注已被 2026-09-15 的全局去标志决策替代。

## 2026-09-10：补齐元任务集合避免导航断档

- 背景：元任务集合位于筹划计算与大区域筹划之间，阶段 4 第一批跳过后会形成已知菜单入口断档。
