# 决策记录

## 2026-09-17：保留现有 React/Vite 项目栈

- 背景：产品目录已存在 React、TypeScript、Vite 和 Tailwind CSS 初始化工程，`prototype.config.json` 标记为历史 React 栈。
- 决定：阶段 1 保留当前技术栈，不迁移、不混入 Vue 或 Element Plus。
- 原因：避免破坏已有项目边界，并保持两套原型可以独立运行。
- 影响：视觉规范通过本项目样式实现；不引入额外 UI 组件库。

## 2026-09-17：采用独立端口的跨系统链接

- 背景：任务规划系统与轨道计算系统位于不同产品目录。
- 决定：任务规划运行在 `127.0.0.1:5173`，轨道计算系统运行在 `127.0.0.1:5174`，顶栏使用标准链接互相跳转。
- 原因：保留独立构建与运行边界，同时满足整体联动展示。
- 影响：使用前需分别启动两个本地预览服务。

## 2026-09-24：保持两个独立原型仓库，仅复用统一壳层联动

- 背景：任务规划系统与轨道计算系统共享 SP-MCS 顶栏和跨系统菜单，但业务、部署与版本迭代边界不同。
- 决定：任务规划保留在 `D:\27原型\task-planning-prototype`（5173）；轨道计算保留在 `D:\27原型\轨道控制系统`（5174）。不合并源码、依赖或构建产物。
- 原因：两个系统能够独立部署、独立验证，同时通过顶部菜单整体联动展示。
- 影响：跨系统链接只承担导航，不共享运行时状态。

## 2026-09-24：阶段 1 以轨道管理作为证据驱动试点

- 背景：`轨道管理2.html` 和 `轨道管理3.html` 已提供正常页、定轨配置、历史轨道及定轨结果的可见证据。
- 决定：实现该页面及已证实弹层；其他菜单仅完成导航骨架。
- 原因：避免在没有字段或流程证据时扩张业务页面。
- 影响：开始计算的提交反馈、自动定轨规则与异常状态列入待确认。

## 2026-09-24：阶段 2/3 复用 SP-MCS 标准主题与壳层

- 背景：阶段 2 视觉评审确认原轨道页面侧栏宽度与主题色同任务规划现行标准不同。
- 决定：用户裁决以任务规划系统作为两个分系统共同的壳层标准。轨道项目的侧栏、品牌区与工作区偏移采用 250px，侧栏背景、48px 菜单节奏、SP 圆章与系统名称表现和任务规划系统一致；SP-MCS 深色顶栏和 `#165DFF` 主色令牌继续保留。
- 原因：两个系统独立部署，但作为同一 SP-MCS 框架菜单下的分系统需要保持一致体验。
- 影响：这是标准化差异，不表述为原轨道系统的像素级原样还原；令牌唯一来源为 `src/index.css`。

## 2026-09-24：阶段 2 待确认交互延期

- 决定：不实现配置保存反馈、历史/结果映射、检索/手动输入/复制流程、历元时间尺度；分页后续页保持禁用。
- 原因：当前 HTML 只确认入口和可见字段，未确认后续业务结果。
- 影响：详细处置见 `docs/reviews/orbit-track-manage-review.md`；新增证据或产品裁决后再扩展。

## 2026-09-24：产品裁决——本地配置、结果上下文与北京时间展示

- 决定：配置保存采用本地回显，不展示真实服务成功/失败；历史轨道与定轨结果按卫星和所选历史记录关联；历元时间展示为北京时间（UTC+8）。
- 原因：产品方已明确配置演示、卫星独立定轨和展示时间要求。
- 影响：MD1B 使用独立数据域，缺少历史明细时不复用 MD1A 数据；前端只格式化已给值，不自行计算星时到北京时间的转换。

## 2026-09-24：手动输入字段确认

- 决定：历史轨道的手动输入弹层保留 TLE 与瞬根单选。TLE 包含 `tle1`、`tle2`；瞬根包含历元时刻、半长轴、偏心率、轨道倾角、升交点赤经、近地点幅角、平近点角，不包含大气阻力系数cd、光压系数cr。
- 原因：产品方提供了两种模式的界面截图，并随后明确要求去除大气阻力系数cd、光压系数cr。
- 影响：只实现已见字段及单位；产品方随后确认保存后直接新增为当前卫星的一条历史轨道记录。原型使用本地生成的临时记录标识，服务端落库和正式编号规则仍待接口证据确认。

## 2026-09-24：历史轨道检索

- 决定：按“数据更新时间”的起止范围筛选当前卫星已经加载的历史轨道记录，点击“检索”后应用筛选；没有匹配项时显示空态。
- 原因：真实页面已确认“数据更新时间”和“检索”入口，产品方明确要求该入口具有交互。
- 影响：本阶段不推断服务端查询、后续分页或跨卫星检索规则。

## 2026-09-24：碰撞预警菜单独立分组

- 决定：将“碰撞预警”和“天体数据”从“轨道控制”菜单组中拆出，归入独立的“碰撞预警”菜单组。
- 原因：产品方明确该两项属于碰撞预警领域，不应被归入轨道控制。
- 影响：保留现有页面路由、字段和操作，只调整左侧导航归属与页面所属分组展示。

## 2026-09-28：阶段 4 统一原型状态与待确认边界

- 决定：所有页面复用同一状态壳层覆盖加载、空、错误和无权限；通过 `?state=loading|empty|error|forbidden` 显式进入验收状态。
- 原因：全量还原需要完整状态覆盖，但没有证据支持真实接口、角色权限、错误码或执行结果。
- 影响：未取证结果明确标注“待确认”；高风险操作仅确认用户提交意图，不伪造服务端成功、失败或进度反馈。

## 2026-11-02 辅助计算产品化

- 坐标与时间转换是标准产品功能表中的保留功能；在 main 提供与 0701 相同的通用页面和计算模块，0701 不另维护算法副本。
- 两体轨道与近似恒星时旋转仅用于原型流程；未接入 UT1、岁差章动、极移或精密星历。时间换算采用 IERS 已公布的 2017—2026 年 TAI−UTC=37 秒，超范围阻止计算。
- 两个工作区已有大量归属未明的未提交页面，本轮只同步辅助计算文件，不将整个项目分支反向合入 main，也不把这些改动归入提交。

## 2026-11-12 事后精密定轨标准版改造

按四张页面截图，将标准版原有静态四步提示替换为可逐步操作的独立 React 页面。原始观测记录、星敏四元数及辅助文件采用集中 Mock；文件选择仅记录名称。计算服务、真实进度及轨道结果缺少规则和接口证据，保持 0% 与空态，避免制造精密计算结果。0701 版仍按既有裁剪不提供该入口；本轮不修改项目分支。

2026-11-13：按复审意见，第一步改为多选并校验所选观测记录的时间覆盖连续；相接或重叠算连续，存在断档则阻止进入第二步或发起计算。第二步移除星敏四元数手选，改为基于所选卫星及观测时间范围的历史遥测定位数据自动查询，原型用集中 Mock 表示查询中、找到和未找到。第四步摘要移除“定轨数据”“辅助文件”，所选观测数据条数按实际数量显示。该页时间统一只标注北京时间，不展示 UTC 偏移。真实查询接口及计算结果待服务接入；0701 裁剪保持不变。

根据页面评审，将四步导航置于左侧并压缩计算摘要。视觉实现复用 GNSS 数据与轨道计算页的查询区、表格和 3px 圆角，不为该页另建大圆角卡片体系；窄宽度下导航改为两列以保留内容宽度。

## 2026-11-13 轨控策略计算复审

按用户两张计算输入参考图重排两种发起方式。当前轨道与监测结果数据放在集中 Mock，自动带入字段只读，引用记录需查得结果才可计算。轨控目标固定为高度修正，修正高度和高度残余偏差用米；修正高度接受正负数，残差未填时不额外推定必填规则。移除双星目标距离和距离残差字段。此轮仅修改标准版；0701 仍维持原裁剪。所有北京时间展示去掉多余的 UTC 偏移文案。

2026-11-13：按后续评审批注，一次轨控策略计算仅选一颗卫星，直接模式改为单选下拉框；引用监测结果回填单颗参与卫星。目标轨道提供“标称轨道高度 / 自定义”，自定义时要求输入目标高度。选星或查询引用记录后，按卫星从集中 Mock 只读回显电推进器标定参数；与推力器标定管理页的初始展示值共用同一组数据。截图仅提供木铎1A参数，木铎1B在原型中使用同组演示参数，真实标定值待接口确认。

2026-11-13：最新评审确认轨控策略计算只能直接使用当前轨道。移除先前设计的“引用轨道保持监测结果”模式、引用记录查询和相关 Mock；发起方式改为只读说明。轨道保持监测页保留原有查询、导出、开始监测、监控设置及查看操作，核对当前标准版代码后没有发现“将结果带入策略计算”的按钮或跳转，因此不额外删除正常的查看入口。轨控计算结果示例的输入来源同步改为当前轨道。此决策覆盖本节前述两种发起方式的历史记录。

2026-11-13：目标轨道选项仍保留“标称轨道高度 / 自定义”，但两者共享“修正高度”和“高度残差”两个数值输入；移除自定义目标轨道高度输入与对应校验。“高度残余偏差”在页面和校验提示中统一改称“高度残差”。
