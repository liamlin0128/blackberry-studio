## 争议项与备选方案

| 争议项 | 影响 | 当前结论 | 备选方案 |
| --- | --- | --- | --- |
| 是否移除顶部“资源管理” | 移除会违背用户确认的跨系统公共能力层级 | 不采纳专家移除建议 | 后续建设公共应用菜单，但需重新确认信息架构 |
| 列表批量“规划计算/区域筹划”是否直接跳转 | 跳转需要确认多选任务如何传参及目标页如何接收 | 不改业务流，只将提示改为“批量参数与跳转规则待确认” | A：仅允许单选后跳转；B：创建批量筹划任务后跳转 |
| 证据总数与少量 Mock 行的分页关系 | 改成 Mock 数量会丢失 239/793 的原系统证据；保留则页码为展示态 | 暂保留证据总数与分页骨架 | A：补齐逐页 Mock；B：显示“证据总数”并禁用未知页码 |
| 是否删除单页签关闭符号、设置齿轮及空菜单分组 | 删除更简洁，但会改变原系统布局骨架和未来信息架构表达 | 本轮不改 | A：确认单页模式后移除；B：实现真实多页签与工作区设置 |
| 1024px 大区域是否改上下布局 | 上下布局可增加字段宽度，但会破坏已评审确认的双列等高关系 | 保留当前双列弹性布局 | 在真实地图或字段继续增加时，于 1050–1100px 切换上下布局 |
| 是否替换“木铎1A/1B” | 替换会破坏 HTML 与页面证据的逐项对应 | 保留并作为证据样例数据 | 产品数据脱敏规则确认后改为通用星名 |
| 优先级颜色是否统一中性化 | 中性化避免误读，但会改变当前可扫描性 | 本轮保留 | 等业务确认优先级语义后建立正式颜色映射 |

## 代码精简结果

- 删除 Pinia 初始化与直接依赖；主入口不再创建未使用 Store。
- 合并两份 `PrototypeState` 为 `src/types/prototype.ts`。
- 删除不存在 DOM 对应的页面标题选择器和过宽的全局弹层 footer 规则。
- 结果统计不再硬编码“4 次拍摄 · 3 天完成”。
- 保留承担布局作用的 `.filter-spacer`、领域组件及证据 Mock，不做误删。
