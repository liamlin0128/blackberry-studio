# 卫星管理试点独立评审意见单：专家 B

评审范围：业务保真、交互流程、状态反馈、可用性。独立查阅 `docs/evidence-inventory.md`、`docs/phase-1-coverage.md`、`卫星管理1.html` 至 `卫星管理10.html`、`src/views/SatelliteListView.vue` 和 `src/mocks/resources.ts`；未参考专家 A 的意见。以下为专家原意见，处理结论见 [汇总评审](task-list-review.md)。

| ID | 分类 | 原意见描述 | 对应证据 | 优化建议 |
| --- | --- | --- | --- | --- |
| B-01 | 业务保真 | 更新时间筛选丢失时分秒，边界日可能误收不符合条件的记录。 | 原 HTML 的筛选控件为 `el-date-editor--datetimerange`，占位是“开始时间/结束时间”；当前页面 `type="daterange"`，`byDate` 用 `updatedAt.slice(0,10)` 比较。 | 改为日期时间范围并按完整时间戳比较，明确北京时间 UTC+8 的包含边界。 |
| B-02 | 布局 | “导出”从原筛选区挪到新增/删除工具栏，弱化了它与当前查询结果的关系。 | `卫星管理1.html` 中查询、重置、导出同在 `ty-tools`；当前 `list-actions` 把导出、新增、删除并排。 | 按原页面把导出放回查询操作区，新增/删除保留列表操作区，并确认导出范围文案与当前筛选一致。 |
| B-03 | 交互 | 删除、编辑保存、新增时段、保存全部、导出执行后缺少明确结果反馈；成功与未生效难以辨别。 | `removeSelected`、`saveEditor`、`savePeriod`、`saveStations` 仅改变内存或关窗；`exportRows` 触发下载后也不提示；仓库 `AGENTS.md` 要求高风险动作有确认和结果反馈。 | 每个操作显示成功/失败或“仅当前会话生效”的反馈；删除保留现有确认，并反馈删除数量；导出提示本次导出条数。真实服务端结果仍标待确认。 |
| B-04 | 业务保真 | 原编辑表单的必填提示丢失，保存只校验卫星 ID 和中文名，容易形成外观上可保存、业务上明显不完整的卫星。 | `卫星管理2.html` 的 `is-required` 包括中文名、英文名、ID、国际编码、类型、组网、预计寿命、轨道高度、侧摆轴转速、偏航轴转速、批次号、卫星编号；当前这些表单项无必填标识，`saveEditor` 仅判断 ID/中文名。 | 先还原已见的必填星号，对已能确认的空值做基础阻止与定位；更细的取值规则列入 B-11 待裁决。专家补充：既有模拟记录缺少若干必填字段，直接全量强制校验会阻断编辑保存。 |
| B-05 | 业务保真 | 光学载荷“编号不大于16个字符”的业务说明未呈现。 | `卫星管理3.html` 明写“每增加一个载荷，都会跟随一个编号，需要手动给该载荷一个本卫星的编号，不大于16个字符”；当前仅有 `maxlength=16`，无说明，且可新增空载荷后保存。 | 保留原说明、显示字符上限；新增载荷未填完整时给明确反馈，不让用户以为空载荷已建立。 |
| B-06 | 缺陷 | 星上站点行内“确定”不是真正的提交门槛，未点击确定也可“保存全部”写入空白或未完成行。 | `addStation` 立即向 `stationRows` 加空行；行内“确定”只是切换 `editingStationId`；`saveStations` 无校验，直接复制所有行。 | 区分编辑草稿与已确认行；保存全部前阻止空白/未确认行并定位。槽位冲突、设备选择规则另待用户裁决。 |
| B-07 | 业务保真 | MD1B 列表显示光学载荷为 1，但点“查看”进入载荷页得到空白配置行，信息自相矛盾。 | `src/mocks/resources.ts` 中 MD1B `payloadCount:1`；`openEditor` 只有 MD1A 给 PMS 默认，其他卫星回退为空载荷。 | 从保存证据补全 MD1B 详情；若证据缺失，用“详情未采集”展示，避免把未知数据伪装成空配置。 |
| B-08 | 交互 | 新增时段的开始/结束时间输入未标时区，而列表/时段表格已标“北京时间 UTC+8”，用户不易确定所填时间的时区。 | `periodEditorOpen` 两个字段仅写“开始时间/结束时间”；表格列头已标时区；仓库 `AGENTS.md` 要求时间必须标明时区。 | 在输入标签或弹窗说明中明确北京时间 UTC+8；编辑弹层内工作时段表格也同步标注。 |
| B-09 | 布局 | 大屏表格横向滚到右端后，操作列之后出现明显空白，削弱行数据与卡片边界的对应关系。 | 用户补充截图中表格内容在卡片右侧结束，而卡片仍延伸出约三分之一空区；当前表格固定列宽且操作列 `fixed="right"`。 | 检查表格与卡片容器宽度、固定列和滚动容器计算，让表格背景、行分隔与操作列填满可视表格区域；不要靠增加虚构字段填白。 |
| B-10 | 业务保真 | 若干原系统关联选择字段被改成自由文本，可能允许不可选的业务值。 | `卫星管理2.html` 中“批次号”为大/小批次选择组合，“卫星编号”和“关联模型”为 `el-select`；当前三者分别是普通 `el-input`。 | 请产品方确认选项来源、批次组合关系与无匹配处理，再还原联动选择；不要臆造选项。 |
| B-11 | 建议 | 新增/编辑表单的完整默认值、下拉全集、数字范围与站点槽位冲突规则没有证据，当前仅凭少量值就允许保存。 | `docs/evidence-inventory.md` 的“待确认”明确列出这些缺口；当前类型只给“遥感卫星”、状态只给“工作”、时段状态只给“维护”，站点槽位任意文本。 | 由用户确认业务规则；确认前在界面上区分可编辑试填与已验证的业务配置，避免将单个示例值误示为全集。 |
| B-12 | 建议 | 加载、错误、无权限、正式空列表状态没有页面证据，原型尚不能让评审者走通这些路径。 | `docs/evidence-inventory.md` 和 `docs/phase-1-coverage.md` 均明确未还原；仓库总 `AGENTS.md` 要求覆盖正常、加载、空、错误、无权限和关键命令确认状态。 | 请用户明确这些状态是否采用统一产品规范的占位设计与文案；实现时标明“原系统待核”，避免宣称业务保真。 |
